# Database setup

The application uses the MySQL database configured in `config.php` (default: `studentsID`). Run the additive migration from a Windows command prompt after placing the project in XAMPP:

```text
C:\xampp\php\php.exe C:\xampp\htdocs\STUDENTID\database\migrate.php
```

The migration creates missing application, supporting log/token, student service-request, faculty/course catalog, system-settings, admin-announcement, admin-notification and authoritative student-registry tables. It adds missing student-registration and card-application fields without dropping or replacing existing tables or records. It is safe to rerun. If duplicate student identifiers prevent a required unique index, the migration stops and reports the duplicate instead of changing student data.

Student application photographs, signatures, and uploaded payment receipts are stored outside the web root in `C:\xampp\STUDENTID-private\students\<database-student-id>\`. Ensure the XAMPP/PHP process can create and write to this directory. The portal serves a file only after checking that it belongs to the signed-in student's own application.

For student ID card applications, students upload the original Canon JPEG with its camera EXIF manufacturer metadata and a signature image. The JPEG itself is used as the card portrait; a separate background-removed cutout is not required. The server checks Canon metadata and image dimensions, but EXIF metadata can be forged and is not proof of camera provenance, so staff should visually review each photo. Card identity fields, including registration number, are saved from the student's editable application form. Administrators maintain faculties/courses and upload the Academic Registrar signature at `http://localhost/STUDENTID/admin_faculties_courses.php`. Card expiry is December 31 of the stated graduation year. Date of issue is shown from the card's recorded issue timestamp; legacy cards without that value show it as unrecorded.

The migration is CLI-only. Update the MySQL credentials in `config.php` if your local XAMPP setup uses a password or a non-default database account.

Administrators and staff sign in through `http://localhost/STUDENTID/login.php`. Both `admin_dashboard.php` and `staff_dashboard.php` open the shared admin console, whose hamburger menu contains the database-backed management, application, service-request, print-queue, reporting and system pages. Administrators maintain the authoritative enrollment list at **Student Registry**: import `.xlsx` workbooks or Excel-exported `.csv` files with `registration_number` and `full_name` headers, optionally including `course` and `programme`; add or edit entries individually; and search the complete list with bounded pagination. Imports are atomic and reject invalid or duplicate registration numbers without partially adding rows. Keep registration numbers formatted as text in Excel if they contain leading zeroes. Student signup requires an active registry entry whose registration number and full name match; existing accounts and records are not removed. If uploads are rejected by PHP before reaching the application, set `upload_max_filesize` and `post_max_size` in `php.ini` to at least 10 MB. Student details include application, card, payment and service-request history; payment receipts are served from private storage after staff authentication. Active admin announcements appear on student panel pages. The migration does not create or reset login accounts; use an existing active administrator account, or have an administrator create staff accounts from the Staff Management page.
